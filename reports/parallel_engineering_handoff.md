# Parallel Engineering Handoff

Engineering/QA/integration agent work log, written in parallel with the ML
agent (Claude). Scope: everything around the ML core — none of the datasets,
labels, splits, training scripts, or model decisions were altered by this
agent except where explicitly noted as a documented, non-ML fix.

## 1. Findings (repository audit)

- Architecture was already sound before this work: no-fabrication discipline,
  typed dataclasses, leakage-audited dataset build, confidence gating.
- No hard-coded absolute paths in `src/` or `app/` (all `pathlib` +
  repo-root-relative).
- Existing tests covered quality checks, morphology basics, comparison logic,
  uncertainty basics, and Streamlit absent-model states.

## 3. Fixes made (engineering)

- **`src/errors.py`** (new): typed error taxonomy — `USER_ERROR`,
  `DATA_QUALITY`, `MODEL_STATE`, `INFERENCE_FAILURE`,
  `SCIENTIFIC_LIMITATION`. `AnalysisError` subclasses `RuntimeError` for
  backward compatibility.
- **`src/inference/contracts.py`** (new): single source of truth for pipeline
  status strings, JSON-safe serialization (None stays None), and schema
  validators (`validate_single_cell_result`, `validate_whole_smear_result`).
- **`src/inference/single_cell.py`**: checkpoint validation (missing keys,
  corrupt file, arch mismatch → `ModelArtifactError`), per-stage typed
  failures, Grad-CAM degradation preserves the prediction, morphology
  serialized via `to_dict()` (UI contract preserved).
- **`src/inference/whole_smear.py`**: box clamping, degenerate-box skipping,
  per-cell classifier failure → `wbc_unresolved` (never aborts the smear),
  all-but-degenerate detections → explicit `NO_CELLS_DETECTED`, contract
  statuses, `to_dict()` on results.
- **`app/utils/model_access.py`**: `classifier_status()`/`detector_status()`
  with explicit pending-state messages.
- **App pages**: honest pending states, error handling, comparison page now
  surfaces per-cell confidence/quality instead of silently using labels,
  Cell Explorer bounds-safe cropping.
- **`.gitignore`**: generated `configs/txl_pbc_detection.yaml` (machine-
  specific absolute path, regenerated by `train_detector.py` each run),
  `.streamlit/secrets.toml`.
- **Streamlit API migration**: all `use_container_width=True` →
  `width="stretch"` (8 occurrences; removal was announced for 2025-12-31).
- **README**: current model status section, structure, reproducibility steps.

## 4. ML issues discovered but intentionally NOT changed

- **Training reproducibility gap (ML agent's call):** `scripts/train_classifier.py`
  sets no `torch.manual_seed` / `numpy` seed, and `scripts/train_detector.py`
  passes no `seed=` to Ultralytics. The dataset *split* is seeded (42), but
  training itself is not reproducible run-to-run. Fixing this changes training
  behavior, so it is left to the ML agent; if adopted, record the seed in the
  eval JSON.
- The two real-data threshold fixes (blur Laplacian 15.0 → 3.0; segmentation
  area floor 2% → 0.3%) were made by the ML agent from measured distributions
  and left exactly as committed.
- Note for the ML agent (documentation only): `temperature <= 0` now raises
  in `classify_with_confidence_gate`; the auto-fitted temperature from
  `TemperatureScaler.fit` is always `exp(...)` > 0, so training-side
  calibration is unaffected.
- Note: `scripts/train_detector.py` writes `configs/txl_pbc_detection.yaml`
  with a machine-specific absolute path. It is regenerated on every run and
  now gitignored — no action needed, just do not commit it manually.
- Note: `requirements.txt` pins `pandas`/`PyYAML`/`scipy` which no first-party
  module imports directly (they are transitive deps of streamlit/ultralytics/
  sklearn). Left as-is: removing pins mid-training is riskier than the
  cosmetic benefit. Revisit at deploy time.

## 7. Reproducibility / deployment audit (second pass)

- **Import-path fragility fixed:** tests previously only worked when invoked
  from the repo root (`python -m pytest`). Added root `conftest.py` (puts the
  repo root on `sys.path`) + `pytest.ini` (`testpaths = tests`, pins rootdir).
  Verified: `pytest` now passes from repo root, from `tests/`, and from an
  unrelated CWD.
- **CWD-independence verified** for the app: model paths resolve via
  `Path(__file__).resolve().parents[2]` regardless of working directory.
- **No Windows-specific APIs** in `src/`/`app/` (no `winreg`/`msvcrt`/
  `os.system`/`cv2.imshow`); `torch.load(..., map_location="cpu",
  weights_only=True)` everywhere; `opencv-python-headless` (no GUI deps);
  `torch==2.14.0+cpu` builds exist for cp310–cp314 on manylinux and win.
- **`runtime.txt` (`python-3.14`)**: torch 2.14.0 publishes cp314 manylinux
  wheels, so the pin is installable on Linux; Streamlit Cloud's actual
  runtime selection remains a deploy-time check (already flagged as an
  explicit open item in `architecture_decision.md` section 12).
- **Classifier inference determinism verified**: same image → identical
  logits/probs across repeated forward passes (eval-mode CNN, no dropout).
- **`yolov8n.pt`** (Ultralytics base weights, auto-downloaded at repo root by
  the active detector training) is covered by the `*.pt` gitignore rule —
  do not commit it.
- **`scripts/evaluate_detector.py`** (ML agent's, added this session) reads
  only the immutable TXL-PBC test split and writes
  `evaluation/detector_v1_detailed_evaluation.json` — no conflicts with
  engineering files.
